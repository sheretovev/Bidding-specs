# Conformance Audit — 2026-08-31

Full read-through of both platforms against every rule in `domain/*.md`, done independently
per platform by tracing actual code paths (not keyword search) and citing file:line evidence.
This supersedes the "conforms well" summaries in `platform-notes/web.md` and
`platform-notes/ios.md` written when this spec was first drafted from a partial reading of
both codebases — several of those early "conforms" calls were correct, several were not.

**Headline: neither platform fully implements the spec, and the gaps are largely
non-overlapping.** iOS is meaningfully stronger on lifecycle-gating, anti-sniping, and
real-time reconciliation. Web is meaningfully stronger on fulfillment, max-bid leading
status, and bidder-identity masking. A bidder moving between the two apps today gets
different guarantees depending which one they're on — which is exactly the drift this repo
exists to eliminate.

## Prioritized punch list

Ranked by user-facing impact on the core bidding journey, not by file count.

1. **`bidding-web`: add the Running-State gate to `LotBidding.jsx`** (SPEC-LOT-002/003,
   SPEC-BID-001). This is the single highest-impact fix — right now the web app lets a user
   attempt a bid the server always rejects, on any lot in any state, with no client-side
   signal telling them why. iOS already has the exact pattern to port (`LotBiddingCard.canBid`).
2. **`bidding-app`: mask other bidders' identities in bidding history** (SPEC-BID-005). Real
   full names/company names of every bidder are shown to every other participant. Web's
   `maskUsername` pattern is a direct port.
3. **`bidding-app`: compute max-bid leading/outbid status** (SPEC-MAX-003). A core piece of
   the proxy-bidding feature is currently invisible to iOS users who use it.
4. **`bidding-web`: wire `onBidSuccess` and add the own-action floor** (SPEC-RT-004), and
   **make Max Bid refetch live data directly** (SPEC-MAX-004/MAX-001). Both are the same
   class of bug — a successful action's result isn't reliably reflected until an external
   push happens to arrive.
5. **`bidding-app`: build the Sales Order / fulfillment screens** (SPEC-FUL-001..004). Lower
   urgency than the above only because it's a known, already-documented gap rather than a
   silent one — but a winning iOS bidder currently has nowhere to go.
6. **`bidding-web`: add Auction Type branching** (SPEC-AUC-002) — hide Max Bid and public
   bidding history for non-open auctions.
7. **Both: fix currency handling** (SPEC-I18N-002) — remove hardcoded currency fallbacks,
   and gate every cross-record sum on a currency-equality check (or render a per-currency
   breakdown instead of a single total).
8. **`bidding-web`: real-time reconciliation hardening** (SPEC-RT-002/003/005) — track a
   server timestamp rather than amount-only comparison, reconcile REST vs. push by recency,
   and actually surface `isConnected` somewhere.
9. **`bidding-web`: require sign-in only for bidding, not for viewing history** (SPEC-AUTH-001).

## Features found with no current spec coverage

Both audits independently surfaced platform features the spec doesn't address at all —
worth a deliberate decision (extend the spec, or explicitly mark out-of-scope) rather than
leaving them unowned:

- Web: AI Chat/AI Search, standalone Asset browsing as a first-class surface, self-registration-on-first-access, UI localization, dashboard mock widgets.
- iOS: Live-update transport switching (WebSocket/long-poll), the in-app Network Debug inspector, decode-drop transparency banners, faceted asset/lot filtering, multi-backend-environment switching.
